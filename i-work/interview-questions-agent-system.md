# iWork Agent 系统设计 — 面试问题集

基于 `agent-client-serve-merry-meerkat.md` 技术详细设计文档。

---

## 一、架构与整体设计

### 必问类（基础）

1. 为什么选择 Client-Server 架构而不是纯客户端或纯服务端方案？各自的优劣是什么？
2. 为什么用 MCP Streamable HTTP 而不是 WebSocket？SSE 和 Streamable HTTP 在你的设计里各有什么取舍？
3. 解释一下这个系统的核心数据流：从用户发消息到收到回复，经历了哪些关键步骤？
4. 三种模式（Ask / Plan / Build）的设计动机是什么？什么场景下用户会选择不同的模式？

### 进阶类

5. 会话工具清单在创建时注册、之后不可变——这种设计的利弊是什么？如果用户升级了客户端、增加了新工具，怎么处理？
6. 消息级配置独立于会话级默认值，为什么历史消息要独立存储配置？这会带来什么存储开销？
7. 如果让你把这个系统扩展到多用户高并发场景，瓶颈在哪？你会在哪些地方做改造？

## 二、Query Loop 引擎

### 必问类

8. 为什么 Per-Message Loop 要串行执行消息（FIFO 队列）而不是并发处理？什么时候并发处理会是更好的选择？
9. 解释一下 `DB + asyncio.Event` 混合方案的队列设计——为什么不用纯内存 `asyncio.Queue`？`FOR UPDATE SKIP LOCKED` 在这个场景解决什么问题？
10. 状态机中的 `WAITING_SYNC` 状态如何处理超时？超时后引擎做什么？
11. Plan 模式中 `plan.question` 的设计——为什么 LLM 要向用户提问而不是生成完整计划后再确认？这会导致什么问题？

### 进阶类

12. 如果一条消息处理中用户发了另一条消息，引擎如何保证不会丢失或乱序？详细说一下入队→排队→出队的完整流程。
13. 连续 3 次相同工具调用检测死循环——这个方法有盲区吗？如果 LLM 故意制造"每隔一次才相同的调用"，你怎么防御？
14. `_check_tool_permission` 中权限拒绝后为什么选择注入错误上下文而非终止？这种"降级"策略在什么场景下会出问题？
15. 服务器重启后，正在处理的消息重置为 `pending` 并从头执行——这是否会导致副作用（如重复文件写入）？你有什么应对方案？

## 三、异常处理

### 必问类

16. 四级异常处理策略的设计哲学是什么？第 2 级"降级"和第 4 级"终止"的边界在哪？
17. 流连接断开时的缓冲回放机制——buffer 上限 500 条，超出后会丢弃什么？如果用户离线很久（比如合盖一晚上），回来看到的是什么？

### 进阶类

18. LLM 流中断后重试 1 次——为什么只重试 1 次而不同于普通网络重试的 3 次？断点续传为什么在流式 LLM 场景不可行？
19. 你的系统里有很多超时时间：消息总耗时 300s、Plan 等待 300s、Client 工具回传 120s、Hook 超时可自定义……这些数字怎么定的？如果场景差异很大（比如 MCP 工具可能需要 5 分钟），怎么优雅配置？
20. `sync_waiter.wait()` 等待用户确认时，如果用户永远不回应，`WAITING_SYNC` 状态会永远卡住吗？资源（内存/数据库连接）会泄漏吗？

## 四、MCP 工具集成

### 必问类

21. MCP 工具和客户端工具的核心区别是什么？为什么 MCP 工具在服务端执行而客户端工具在 Electron 端执行？
22. 为什么 MCP 工具名要加 `{server_id}_` 前缀？不加会有什么问题？
23. 三种传输方式（stdio / SSE / Streamable HTTP）分别适用于什么场景？如果让你选一种作为推荐方式，你选哪个、为什么？

### 进阶类

24. MCP 凭据通过 `${ENV_VAR}` 引用，如果环境变量在运行时被修改（比如用户改了 .env），正在运行的 MCP 进程会感知到吗？你的系统如何处理凭据轮换？
25. 如果两个 MCP 服务提供了同名的工具（如两个服务都有 `search`），虽然加了前缀、但 LLM 看到的功能描述相似，它会选错吗？除前缀外你还有什么手段帮助 LLM 区分？
26. MCP 工具发现流程为什么放在客户端而非服务端？这样设计有什么好处和代价？

## 五、Skill 集成

### 必问类

27. Skill 和 MCP 的本质区别是什么？为什么 Skill 的核心指令在客户端读取而不是服务端？
28. `<available_skills>` XML + `skill` 工具的设计：为什么 Skill prompt 不是常驻 system prompt 而是 LLM 按需调用？这样做的好处和可能的漏用风险？
29. 用户输入 `/skill名` 的预加载流程 vs LLM 自己选择 skill，这两条路径分别适用于什么场景？

### 进阶类

30. Skill 安装时返回 zip 包，客户端解压——为什么不是服务端直接读写？这种"客户端持有核心指令"的设计，在多设备同步时会出现什么问题？
31. 如果一个 Skill 的 SKILL.md 在 Install 后被用户手动修改了，系统能检测到吗？如何保证 Skill 执行的幂等性和一致性？
32. Skill 不像 MCP 那样有凭据管理——但如果有 Skill 需要调用外部 API（比如需要 API Key），你的系统怎么处理？

## 六、记忆模块

### 必问类

33. 四种记忆类型（user / feedback / project / reference）的划分逻辑是什么？为什么"什么不保存"的清单和保存清单一样重要？
34. MEMORY.md 索引的动态生成——为什么不是一条 DB 记录而是每次查询拼装？200 行上限的原因是什么？
35. Rules 和 Memory 的核心区别：为什么 Rules 只能用户手动写入、AI 只读？如果 AI 判断某条规则已过时，它能做什么？

### 进阶类

36. AI 主动写记忆时，如何避免写入错误或重复的信息？`write_memory` 工具描述里提到"检查是否已有且内容一致"，但 LLM 的"检查"能力有多可靠？
37. 如果用户说"不要再记住我的编码风格"，LLM 调用 `delete_memory` 删除了一些记忆。但之前的对话中 LLM 已经用这些记忆做过决策了——这会导致什么问题？
38. `protected` 标记是什么场景下用的？为什么用户手动删除时不区分 protected，而 AI 调用 `delete_memory` 时要检查？

## 七、可观测性

### 必问类

39. 为什么 Tracing / Metrics / Logging 走各自的 API（OTel / structlog）而只有 Stream + Audit 走 EventBus？这种设计选择背后的原则是什么？
40. "零翻译"的 chunk 同名事件设计——为什么 `StreamSubscriber` 拿到 `AgentEvent.data` 能直接当 NDJSON 推送？这样省了什么？
41. 如果让你们团队在生产环境排查一次 AI 回复错误（"为什么 LLM 改了这个文件？"），你会怎么用你设计的可观测性体系来定位问题？

### 进阶类

42. 审计日志"存元数据不存本体"——优点和风险分别是什么？如果审计时发现某次 `shell_exec` 有问题，但完整输出不在审计表里，你怎么回溯？
43. 本地兜底方案（文件轮转 + metrics snapshot + grep trace_id）在什么量级下会扛不住？你如何决定何时升级到 Grafana 全套？

## 八、Hooks 系统

### 必问类

44. Hooks 的责任链模型与 EventBus 的发布-订阅模型的本质区别是什么？为什么 Hooks 要等结果而 EventBus 不用？
45. Hook 超时或异常时"视为 CONTINUE"——为什么不终止执行？如果一个安全审计 Hook 因为超时被跳过了，危险命令就会被执行——你如何保证安全 Hook 不会被跳过？

### 进阶类

46. Hook 的 `MODIFY` 返回值可以修改 `tool.before` 的参数——如果两个 Hook 都在改同一个参数，以谁为准？你如何处理 Hook 执行顺序带来的竞态？
47. `message.before` 如果被 Hook STOP 了，消息算处理完成还是处理失败？队列中的下一条消息会如何处理？
48. Hooks 安全模型里提到"Hook 子进程不继承敏感环境变量"——但如果 Hook 脚本本身需要 API Key 才能工作（比如 teams-webhook.sh 需要 Webhook URL），它怎么拿到这个配置？

## 九、多 Agent 协作

### 必问类

49. 为什么选星型拓扑而不是网格拓扑（子 agent 之间可以通信）？星型拓扑的主要瓶颈是什么？
50. `task` 工具设计中为什么用单一工具 + `agent_name` 枚举，而不是每个子 agent 注册一个独立工具？这两种设计的利弊是什么？
51. 为什么要禁止子 agent 再调用 `task` 工具？如果没有这个限制，可能出现什么问题？

### 进阶类

52. 子 agent 在隔离 session 中独立运行——子 agent 能看到主 agent 的上下文吗？如果不能，主 agent 怎么把关键信息传递给子 agent？
53. 如果主 agent 让 3 个子 agent 并行处理不同文件，但有一个子 agent 失败了——主 agent 怎么知道？失败后应该重试还是换策略？
54. 这个多 Agent 系统如何处理子 agent 产出冲突（比如两个子 agent 都改了同一个文件）？
