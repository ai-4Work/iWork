## 上下文管理功能概览

> LLM 的上下文窗口有限。上下文管理组件在有限窗口内尽量保留关键信息：把旧内容压成摘要（**压缩**）、把低价值内容移出窗口（**卸载**）、需要时再找回（**召回**）。

### 核心概念

- **块（InfoBlock）**：压缩 / 卸载 / 召回的最小原子单元，通常是一段 tool_result 或 assistant 内容。
- **产物（artifact）**：块上的字符串标签，记录该块操作的目标文档，用于分组合并与卸载索引。

### 三大主要功能

1. **压缩**：估算 token 超过窗口阈值时，把旧内容压成摘要。分两个粒度——先「单块压缩」把单个大块摘要，仍超限再「合并压缩」把同一产物的多个块合并成一个摘要。
2. **卸载**：压缩后仍超限时，按 `retention_score` 三档分流（保留 / 落库 / 丢弃），把低分块移出窗口；落库块在窗口内只留索引。
3. **召回**：需要旧信息时找回。分两种——**被动召回**（系统用最新消息自动匹配，注入 system_prompt）和**主动召回**（LLM 调用 `recall` 工具检索已卸载块）。

### 三个日志标记

以下三个标记只出现在 `context_payload` 日志里，用于判断各功能是否触发（UI / 输出流不展示）：

| 标记 | 含义 | 注入位置 |
|---|---|---|
| `[压缩历史]` | 更早对话被压缩后的摘要块 | messages（SUMMARY → user 消息前缀） |
| `[可用外部记忆]` | 本轮有块被卸载后，窗口内注入的索引区 | messages（SUMMARY 块第 0 位） |
| `[召回记忆]` | 被动召回命中，注入的记忆片段 | system_prompt 末尾 |


## 1. 黑盒/场景测试用例（面向测试人员）

> 本章面向 QA/测试人员，从「用户/系统可观察层面」描述：**怎么操作、看什么、什么算通过**。粒度到场景，不涉及内部实现。操作方式为通过客户端/接口进行真实多轮对话。

### 1.1 测试准备（必读）

| 项目 | 说明 |
|---|---|
| 启动服务 | `python -m uvicorn server.main:app --host 127.0.0.1 --port 8000` |
| 建会话 | `POST /sessions`，请求体可带 `mode`（`ask` / `build` / `plan`）、`model` 等 |
| 发消息 | `POST /sessions/{id}/messages`，请求体带 `content`（正文）、`mode`（本轮模式）等，返回 NDJSON 流 |
| 快速触发 | 在 `.env` 写入 `IWORK_MODEL_CONTEXT_LIMIT=1000`（默认窗口较大，不调小需堆几十轮才触发）。改后重启服务生效 |
| **观察方式** | **压缩/卸载/召回不会在界面弹 toast，主要看日志** |

**日志观察要点**（stdout 控制台 + `logs/agent.log`，JSON 按天轮转）：

| 日志字段 | 含义 |
|---|---|
| `context_compressed` | 本轮发生了上下文压缩 |
| `blocks_offloaded` | 本轮发生了卸载（低分块落库/丢弃） |
| `context_payload` | 每轮实际发给 LLM 的完整上下文（能看到压缩/卸载/召回后的最终效果） |

三个标记字符串**只出现在 `context_payload` 里**（UI/输出流不直接展示）：

| 标记 | 含义 |
|---|---|
| `[压缩历史]` | 更早的对话被压缩后的摘要块（`SUMMARY` → user 消息前缀） |
| `[可用外部记忆]` | 本轮有块被卸载后，窗口内注入的索引区（每行 `· label (turnN)`） |
| `[召回记忆]` | 被动召回命中，注入到 system_prompt 的记忆片段 |

**触发前提**：轮次 > 3（`raw_turns=3` 以内不压缩）且估算 token ≥ 窗口 × 阈值。压缩阈值按模式区分：`ask=0.55`、`build/plan=0.80`。

### 1.2 压缩模块

> 压缩分两个粒度：先「单块压缩」（粒度1，把单个大块摘要），仍超限再「合并压缩」（粒度2，把同一产物的多个块合并成一个摘要）。下方先列触发与整体行为用例，再按两个粒度列具体压缩手段。

**触发与整体行为**

#### E2E-CMP-01 短对话不压缩
- **前置**：默认窗口（不调小），新建 `build` 会话。
- **步骤**：连续发送 2~3 条简短消息（如「你好」「介绍一下你自己」）。
- **预期**：日志中**不出现** `context_compressed`；`context_payload` 中历史消息均为原文、无 `[压缩历史]` 标记。

#### E2E-CMP-02 长对话/超阈值触发压缩
- **前置**：`.env` 设 `IWORK_MODEL_CONTEXT_LIMIT=1000`，重启服务；新建 `build` 会话。
- **步骤**：连续发送 4 条以上消息，每条 `content` 粘贴几百字长文本（或让 agent 读大文件累积 tool_result），使估算 token 超过 `1000 × 0.80`。
- **预期**：日志出现 `context_compressed`；`context_payload` 中出现 `[压缩历史]` 摘要块，较早的历史被压缩为摘要、原文变短。

#### E2E-CMP-03 ask 比 build 更早压缩
- **前置**：`.env` 设 `IWORK_MODEL_CONTEXT_LIMIT=1000`，构造一批估算 token 落在 `1000×0.55 ~ 1000×0.80` 之间的消息。
- **步骤**：用**相同**这批消息分别以 `mode="ask"` 和 `mode="build"` 发起。
- **预期**：`ask` 模式触发压缩（日志出现 `context_compressed`）；`build` 模式**不**触发（阈值 0.80 未达）。

#### E2E-CMP-04 最近 raw_turns 轮原文保留
- **前置**：同上（已能触发压缩），累计 8 轮以上对话。
- **步骤**：持续对话触发压缩后，查看最近一轮的 `context_payload`。
- **预期**：**最近 3 轮**（`raw_turns=3`）的历史消息保持完整原文；更早的轮次被压成 `[压缩历史]` 摘要。滑动窗口内的内容永不压缩。

#### E2E-CMP-05 压缩前后 token 显著下降
- **前置**：同上（能触发压缩）。
- **步骤**：触发压缩后，取 `context_payload` 对比压缩前后（或看 `context_compressed` 日志附带的 token 字段）。
- **预期**：压缩后上下文 token 明显下降；`compression_ratio`（压缩后/原始）介于 0~1 之间，且压缩后 token ≤ 原始 token。

**单块压缩（粒度1）**

#### E2E-CMP-06 大工具返回被摘要压缩
- **前置**：同上；准备一个内容 200~10000 token 的文件。
- **步骤**：让 agent 读取该文件（如「读一下 src/xxx.sql 并总结」），再继续对话至触发压缩；对比压缩前后的 `context_payload`。
- **预期**：该文件的 tool_result 在压缩后从长篇原文变成 1~2 句摘要（在 `[压缩历史]` 或压缩后的 tool 内容中可见）。

**合并压缩（粒度2）**

#### E2E-CMP-07 同一产物多次读写被合并为摘要
- **前置**：`.env` 设 `IWORK_MODEL_CONTEXT_LIMIT=1000`，重启；新建 `build` 会话。
- **步骤**：在对话**早期**（约 10 轮之前）围绕**同一个文件**（如 `src/top50.sql`）多次操作（如「读一下 top50.sql」→「按我的要求改 top50.sql」→「再读 top50.sql 确认」），之后再继续对话多轮以触发压缩。
- **预期**：`context_payload` 中，早期针对 `top50.sql` 的**多个** tool_result / assistant 块被合并成**一个** `[压缩历史]` 摘要块（同一产物归并为一个 SUMMARY）；对比压缩前后，该文件的块数明显减少、合并为单个摘要。

### 1.3 卸载模块

#### E2E-OFF-01 压缩后仍超限触发卸载
- **前置**：`.env` 设 `IWORK_MODEL_CONTEXT_LIMIT=1000`；构造压缩后估算仍 > `1000 × 0.75` 的输入（多轮大文本）。
- **步骤**：持续对话触发压缩与卸载。
- **预期**：日志出现 `blocks_offloaded`；`context_payload` 中出现 `[可用外部记忆]` 索引区（列出被卸载块的 label 与 turn）。

#### E2E-OFF-02 三档分档（保留/落库/丢弃）
- **前置**：同上；对话中制造不同类型内容——高价值稳定结论（保留）、中等价值结果（落库）、一次性/过时的大工具返回（丢弃）。
- **步骤**：触发卸载后，查看日志 `blocks_offloaded` 与数据库表 `offloaded_blocks`（或日志附带的卸载明细）。
- **预期**：按 `retention_score` 三档分流——`≥0.60` 保留在窗口；`0.30~0.60` 写入 `offloaded_blocks` 表（窗口留索引）；`<0.30` 直接丢弃（不落库）。

#### E2E-OFF-03 卸载后窗口降到阈值以下
- **前置**：同上（已触发卸载）。
- **步骤**：触发卸载后查看 `context_payload` 的 token 量。
- **预期**：卸载后窗口 token 显著下降，目标降到窗口的 **45% 以下**（卸载停止线），低分块已移出窗口。

#### E2E-OFF-04 未触发卸载时不产生空索引
- **前置**：构造仅触发压缩、但压缩后已 ≤ `0.75` 窗口（不再需要卸载）的输入。
- **步骤**：触发压缩后查看 `context_payload`。
- **预期**：只有 `[压缩历史]`，**不出现** `[可用外部记忆]`（无卸载块时不会插入空的索引头）。

### 1.4 召回模块

#### E2E-REC-01 被动召回注入
- **前置**：先用多轮对话制造一批内容并触发卸载（信息写入 `offloaded_blocks`）。
- **步骤**：再发一条与已卸载内容**语义相关**的新消息（如「刚才那个 SQL 文件里的表结构是什么」）。
- **预期**：`context_payload` 的 system_prompt 中出现 `[召回记忆]` 片段（被动召回命中旧内容，top_k=3 注入）。

#### E2E-REC-02 主动召回取回旧信息
- **前置**：同上（已有卸载内容）。
- **步骤**：提出一个需要早期已卸载信息才能回答的问题，观察 agent 是否调用 `recall` 工具。
- **预期**：agent 主动调用 `recall` 工具，返回 `{"status":"ok","blocks":[...]}`，并基于召回内容给出**正确**回答（被卸载前的关键信息可被找回）。

#### E2E-REC-03 召回无命中
- **前置**：同上。
- **步骤**：问一个与所有已卸载内容**完全不相关**的问题，或直接触发 `recall` 工具查无匹配词。
- **预期**：`recall` 返回 `{"status":"searched_nothing_found"}`，明确告知未找到，不返回空 block 列表，不崩溃。

#### E2E-REC-04 端到端信息保持
- **前置**：新建会话，先提供一条明确的「事实」（如「项目代号是 Mercury」），随后制造长对话使该事实被压缩/卸载出窗口。
- **步骤**：对话末尾再问「我们的项目代号是什么」。
- **预期**：通过压缩摘要或召回，agent 能正确回答「Mercury」，验证压缩/卸载/召回链路**不丢失关键信息**。

### 1.5 注意事项（测试人员）

1. **压缩/卸载不弹 UI 提示**：当前实现只写日志，无 `system.status` toast。判断是否触发请以 `logs/agent.log` 的 `context_compressed` / `blocks_offloaded` 字段为准。
2. **三个标记只存在于 `context_payload` 日志**：`[压缩历史]` / `[可用外部记忆]` / `[召回记忆]` 不会出现在对话输出流里，需从日志的 `context_payload` 字段查看。
3. **轮次 ≤ 3 不会压缩**：`raw_turns=3` 是最小保留窗口，短对话永远看不到压缩，属正常现象。
4. **调 `IWORK_MODEL_CONTEXT_LIMIT` 加速**：默认窗口很大，直接测试需堆几十轮；建议先调小到 1000 再验证，验证通过后调回。
5. **模式决定阈值**：`ask`（0.55）比 `build/plan`（0.80）更激进，比对时务必用相同 `mode`，否则结论不可比。
