## 权限控制功能概览

> 核心定位一句话：**服务端定规则、判三态、生成策略；客户端执行、代理域名审批、沙箱兜底；判定与确认全程走现有 NDJSON chunk 通道**。

### 核心概念

- **三态判定**：每次工具调用前，服务端判出 `Skip`（够格，直接执行）/ `NeedsApproval`（要问人，客户端弹确认）/ `Forbidden`（硬停，连问都不问，注入错误返回模型）。
- **权限画像**：文件系统 + 网络拼成一条画像，整场会话默认共用；内置三档 `:read-only`（全盘只读）/ `:workspace`（工作区可写、其余只读、`.git`/`.env` 强制 deny）/ `:full`（关闭整套权限体系、不建沙箱），可自定义 `extends` 继承。
- **三层拦截**：服务端静态判定（工具级，管要不要问）→ 客户端代理（域名/连接级，管域名规则的强制执行）→ 沙箱兜底（目录/进程级，漏判也拦得住）。
- **三个维度**：① 文件系统读写（`filesystem`）② 网络访问（`network`）③ 工具审批策略（`approval_policy` + `tool_rules`）。前两个拼成画像，第三个独立。

### 判定与确认的载体

- 服务端判定结果 + 策略包随 `client.tool_request` chunk 下发（`requires_approval` + `policy` 字段）。
- 客户端按 `requires_approval` 二分：`false` → **auto-execute** 自动执行（不弹窗）；`true` → **确认流**（确认 / 跳过 / 终止）。
- 客户端执行结果 / 域名审批 / 沙箱 trap 随 `/tool-result` 回传，服务端落审计。

### 日志观察要点

| 观察点 | 含义 | 位置 |
|---|---|---|
| `tool.permission_denied` | 三态 = forbidden 的拒绝事件 | 服务端事件 + 审计（`observability/events.py` `TOOL_PERMISSION_DENIED`） |
| `tool.network_approval` | 客户端域名判定结果（host/decision/approved） | 服务端审计（P2 回传，`NETWORK_APPROVAL`） |
| `permission_evaluate_error` | 引擎异常兜底日志（异常时返回 skip，不误伤） | 服务端日志 |
| 工具卡确认弹窗 | `requires_approval=true` 时展示「确认/跳过/终止」三按钮 | 客户端 UI（`SegmentsView.tsx`） |
| `NetworkConfirmDialog` | 未知域名 + `unknown_domain: ask` 时的域名审批弹窗 | 客户端 UI（顶层 Modal） |
| 沙箱错误文案 | `沙箱不可用：landstrip 未就绪`（fail-closed）或 `沙箱执行失败：...` | 客户端 bash 工具输出 |

## 1. 黑盒/场景测试用例（面向测试人员）

> 本章面向 QA/测试人员，从「用户/系统可观察层面」描述：**怎么操作、看什么、什么算通过**。操作方式为通过客户端/接口进行真实多轮对话，让 LLM 触发工具调用后观察判定与执行行为。

### 1.1 测试准备（必读）

| 项目 | 说明 |
|---|---|
| 启动服务 | `python -m uvicorn server.main:app --host 127.0.0.1 --port 8000` |
| 建会话 | `POST /sessions`，请求体**务必带 `workspace`**（会话工作区绝对路径，用于解析配置里的 `@WORKSPACE@` 符号路径；不带则路径判定失准），可带 `mode`（`ask` / `build` / `plan`）、`model` 等 |
| 发消息 | `POST /sessions/{id}/messages`，请求体带 `content`（正文）、`mode`（本轮模式）等，返回 NDJSON 流 |
| 配置权限 | 改 `server/permissions.yaml` 后**重启服务**生效 |
| 启动客户端 | agent-client（`npx electron-vite dev` 或打包版），建会话并接入，观察 UI 弹窗 / 免确认 / 错误文案 |
| **模式选择** | 客户端默认 **Build 模式**（`modeStore.ts:12` `inputMode:'build'`，输入框右上 Build/Plan/Ask 下拉可切）。Build / Ask / Plan 三态确认粒度一致（`requires_approval=(verdict==needs_approval)`，`query_loop.py:1192/1209`）：**skip 免确认、needs_approval 弹确认、forbidden 拦截**。测「免确认」用例无需切模式 |
| 触发工具调用 | 权限控制的观察点在「工具调用」，需发指令引导 LLM 调用工具（如「读一下 src/a.txt」「git status」「把这个文件写到外面」） |
| **观察方式** | 服务端：stdout 控制台 + `logs/agent.log`（JSON 按天轮转）的事件/审计；客户端：UI 弹窗、工具执行结果、错误文案 |

**日志观察要点**（服务端 `logs/agent.log` + 控制台）：

| 日志字段 | 含义 |
|---|---|
| `tool.permission_denied` | forbidden 拒绝事件（含 tool_name） |
| `tool.network_approval` | 客户端回传的域名判定（host / protocol / decision / approved） |
| `permission_evaluate_error` | 引擎异常兜底 |
| skip 反馈 | 客户端回传 `skipped:true` → 服务端 `append_skip_feedback` 把"用户跳过了"注入上下文 |

**触发前提**：判定只在「工具调用」时发生——LLM 必须真正发起客户端工具调用（`CLIENT_TOOLS`：`bash` / `read_file` / `write_file` / `edit_file` / `glob` / `grep` / `skill`）。让 LLM 不调工具（纯聊天）不会触发任何权限逻辑。

### 1.2 服务端三态判定

> 判定主体在服务端（`server/tools/permission.py`），按工具分类各自逻辑：文件类逐路径、命令类命令前缀、网络类一律放行、其它兜底。三态结果通过客户端行为（免确认 / 弹窗 / 拒绝注入）与服务端日志观察。

**文件类（write_file / edit_file / apply_patch）**

#### E2E-PERM-01 工作区根内写 → skip 自动执行
- **前置**：默认配置（`:workspace` + `on-request`）；Ask / Build 模式均可（均按三态确认，skip 免确认）；建会话并带 `workspace`。
- **步骤**：让 LLM 写一个工作区内的文件（如「新建 src/hello.txt，内容 hi」）。
- **预期**：客户端**不弹确认**直接执行（auto-execute），文件成功写入；日志无 `tool.permission_denied`。

#### E2E-PERM-02 越界写 → needs_approval 弹确认
- **前置**：同上。
- **步骤**：让 LLM 把文件写到工作区外（如「写 /outside/a.txt」）。
- **预期**：客户端**弹确认**（工具卡 pending + 确认/跳过/终止）；点确认后执行、点跳过则不执行。日志无 `tool.permission_denied`。

#### E2E-PERM-03 写保护路径 `.env` / `.git` → forbidden 拒绝
- **前置**：同上（`:workspace` 的 `:deny_workspace` 含 `.git/**`、`.env`）。
- **步骤**：让 LLM 写 `{workspace}/.env` 或 `{workspace}/.git/config`。
- **预期**：**不弹确认**，服务端直接拒绝并注入错误返回模型（客户端看不到 pending 卡）；日志出现 `tool.permission_denied`（tool_name=write_file）。

#### E2E-PERM-04 读 deny 路径 → forbidden
- **前置**：同上。
- **步骤**：让 LLM `read_file` 读 `{workspace}/.env`。
- **预期**：读也被拒（引擎当前 deny 同时拦读与写），不弹确认、注入错误；日志 `tool.permission_denied`。

**命令类（bash / exec_command）**

#### E2E-PERM-05 命令规则 allow → skip 免确认
- **前置**：默认配置（`tool_rules` 含 `git status → allow`）。
- **步骤**：让 LLM 执行 `git status`。
- **预期**：客户端**不弹确认**直接执行，输出 git status 结果；日志无 `tool.permission_denied`。

#### E2E-PERM-06 命令规则 forbidden → 拒绝
- **前置**：默认配置（`tool_rules` 含 `rm -rf → forbidden`、`rm -rf / → forbidden`）。
- **步骤**：让 LLM 执行 `rm -rf /` 或 `rm -rf build`。
- **预期**：命令**不执行**、不弹确认，注入错误返回模型；日志 `tool.permission_denied`（tool_name=bash）。

#### E2E-PERM-07 危险命令启发式 → needs_approval
- **前置**：默认配置（`dangerous_command_heuristics: true`）。
- **步骤**：让 LLM 执行一条命中内置危险模式但不命中 tool_rules 的命令（如 `mkfs.ext4 /dev/sda`、`shutdown -h now` 等）。
- **预期**：客户端**弹确认**（需要问）；日志无 `tool.permission_denied`。

#### E2E-PERM-08 普通命令 → skip
- **前置**：默认配置。
- **步骤**：让 LLM 执行 `ls -la` 等无规则命中的普通命令。
- **预期**：不弹确认直接执行；日志无 `tool.permission_denied`。

**网络类 / 其它**

#### E2E-PERM-09 网络工具服务端一律放行（判定在客户端代理）
- **前置**：默认配置。
- **步骤**：让 LLM 调用 `web_fetch` / `web_search`（或观察 `client.tool_request` 的 chunk）。
- **预期**：服务端对网络工具恒 `skip`（不做域名静态判定），日志无 `tool.permission_denied`；**域名拦截与否看客户端代理**（见 1.5 E2E-NET）。

**审批开关**

#### E2E-PERM-10 `approval_policy: never` 时 prompt 变 forbidden
- **前置**：把 `permissions.yaml` 的 `approval_policy` 改为 `never`，重启服务；重建会话。
- **步骤**：触发一条本该弹确认的命令（如 `mkfs.ext4 /dev/sda`）或越界写。
- **预期**：`prompt` 基调被翻译成 `forbidden`——**不弹确认直接拒**；日志 `tool.permission_denied`。测完改回 `on-request`。

#### E2E-PERM-11 `:full` 画像全部 skip（关闭权限体系）
- **前置**：把 `default_permissions` 改为 `:full`，重启服务；重建会话。
- **步骤**：让 LLM 执行 `rm -rf /`、写任意路径。
- **预期**：全部 skip、不弹确认、不被拒（注意危险：只做观察，不真执行破坏性命令，可改为让 LLM 描述「如果执行会怎样」或查策略包）。测完改回 `:workspace`。

### 1.3 策略包下发

> 服务端每次给 CLIENT 工具下发 `client.tool_request` 时，`policy` 字段随包带出（`build_policy` 从当前画像编译）。策略包是客户端执行/建沙箱的依据。

#### E2E-POL-01 `:workspace` 策略包结构
- **前置**：默认配置；建会话带 `workspace`；客户端开 DevTools 或抓 NDJSON 流。
- **步骤**：触发任意客户端工具（如 `read_file`）。
- **预期**：`client.tool_request` 的 `policy` 字段：
  - `filesystem.profile = ":workspace"`；
  - `allow_write` 含 `workspace` 与临时目录的绝对路径；
  - `deny_write` / `deny_read` 为锚定绝对路径的 glob（如 `{workspace}/.git/**`、`{workspace}/.env`）；
  - `network.enabled = false`；
  - `sandbox.required = true`。

#### E2E-POL-02 `:full` 精简包
- **前置**：`default_permissions: ":full"`，重启；建会话。
- **步骤**：触发任意客户端工具，观察 `policy`。
- **预期**：精简包 `{filesystem: {profile}, network: {enabled: false}, sandbox: {required: false}}`（不展开 allow/deny，不建沙箱）。

#### E2E-POL-03 `network.approval_policy` 随包下发
- **前置**：默认配置（`on-request`），建会话。
- **步骤**：触发工具，观察 `policy.network.approval_policy`；再把 `approval_policy` 改 `never` 重启重测。
- **预期**：默认下发 `"on-request"`；改 `never` 后下发 `"never"`（客户端代理按此做网络总闸）。

#### E2E-POL-04 `network_rules` 编译下发
- **前置**：默认配置（`network_rules` 含 `registry.npmjs.org` allow / `git.example.com` prompt），建会话。
- **步骤**：触发工具，观察 `policy.network.network_rules`。
- **预期**：列表含合法条目（host+protocol+decision）；**缺 host / decision 非法的条目被过滤**（可临时往 yaml 塞一条非法项验证）。

### 1.4 客户端确认流 P1

> 客户端消费 `requires_approval`：`false` → auto-execute 免确认；`true` → 确认流。确认/跳过/终止三按钮复用 Build 确认 UI，泛化到所有模式。

#### E2E-APR-01 skip 工具免确认直接执行
- **前置**：默认配置；自动模式；建会话。
- **步骤**：让 LLM 执行 `git status`（skip）与写工作区根内文件（skip）。
- **预期**：工具卡**不出现 pending / 确认按钮**，直接进入执行并显示结果。

#### E2E-APR-02 needs_approval 弹确认，确认后执行
- **前置**：同上。
- **步骤**：让 LLM 写工作区外文件（needs_approval），点「确认」。
- **预期**：工具卡显示「确认/跳过/终止」；点确认后工具执行、结果回传。

#### E2E-APR-03 跳过 → skip 反馈进上下文
- **前置**：同上。
- **步骤**：让 LLM 写工作区外文件，点「跳过」。
- **预期**：工具**不执行**；`/tool-result` 回传 `{status:'error', skipped:true}`；服务端 `append_skip_feedback` 生效——后续模型能感知「用户跳过了该工具」（上下文注入 skip 反馈）；日志可见 skip 处理。

#### E2E-APR-04 终止 → 会话终止
- **前置**：同上。
- **步骤**：让 LLM 发起需要确认的工具，点「终止」。
- **预期**：停止所有 pending 工具并终止当前会话（`stopTools` + `cancelSession`），不再继续。

#### E2E-APR-05 Build 模式按三态确认（消费 skip）
- **前置**：默认配置；`build` 模式会话。
- **步骤**：Build 会话里先执行 `git status`（skip），再触发越界写（needs_approval）。
- **预期**：Build 下 `git status` **免确认直接执行**（`requires_approval=(permission=="needs_approval")`，`query_loop.py:1192`）；越界写仍**弹确认**；`forbidden` 拦截。确认粒度与普通模式一致，仅多 `step`/`tool_call_id` 字段。

#### E2E-APR-06 断线重连不二次执行
- **前置**：默认配置；自动模式；建会话。
- **步骤**：让 LLM 触发一个 skip 工具，在 `client.tool_request` 到达后、执行完成前断开客户端网络，再重连。
- **预期**：重连按 `since_seq` 重放 chunk 后，该 `request_id` 的工具**不重复执行**（auto-execute 按 `request_id` 幂等）；pending 确认流重连后保持 pending 不丢。

#### E2E-APR-07 多智能体平行 agent 同步
- **前置**：多智能体会话（存在平行 `client.tool_request`）。
- **步骤**：让平行 agent 发起需要确认与可自动执行的工具。
- **预期**：平行 agent 与主 agent 行为一致——skip 免确认、needs_approval 弹确认（`multiAgentStore` 与 `chatStore` 同步）。

### 1.5 域名审批 P2

> 判定主体在**客户端本地 HTTP 代理**：spawn 工具子进程注入 `HTTPS_PROXY` → 代理从 CONNECT 提取 host → 比对服务端下发的白名单 → 未命中先过 `approval_policy` 总闸，再按 `unknown_domain` 细化（`ask` 弹窗 / `deny` 拦）。结果随 `/tool-result` 的 `network_approvals` 回传审计。
>
> **需要网络型画像**：`:workspace` 默认 `network.enabled=false`（全拒）。测网络需自定义画像（如 `dev` 示例：`extends: ":workspace"` + `network.enabled: true` + `domains` + `unknown_domain: ask`），改 yaml 重启、建会话。

#### E2E-NET-01 allow 域名放行
- **前置**：`dev` 画像（`registry.npmjs.org: allow`）；建会话。
- **步骤**：让 LLM 执行联网命令访问 allow 域名（如 `curl https://registry.npmjs.org/...` 或 `npm install`）。
- **预期**：连接正常转发，命令成功；审计收到 `tool.network_approval`（decision=allow、approved=true）。

#### E2E-NET-02 deny 域名拒绝
- **前置**：`dev` 画像（`evil.example.com: deny`）；建会话。
- **步骤**：让 LLM 执行 `curl https://evil.example.com/...`。
- **预期**：代理回 403 / 连接被拦（命令报错），不弹窗；审计收到 `tool.network_approval`（decision=deny、approved=false）。

#### E2E-NET-03 未知域名 + ask → 弹窗批准后放行
- **前置**：`dev` 画像（`unknown_domain: ask`）；建会话。
- **步骤**：让 LLM 访问一个不在白名单的域名（如 `curl https://unknown.example.org`）。
- **预期**：弹出 `NetworkConfirmDialog`（显示 host/protocol）；点「同意」→ 连接放行、命令成功；点「拒绝」→ 连接被拦。

#### E2E-NET-04 批准后同一 host 会话内不再问（会话缓存）
- **前置**：同上。
- **步骤**：第一次访问未知域名时批准；随后再次执行同一 host 的请求。
- **预期**：第二次**不再弹窗**直接放行（会话级缓存 `Map<host, {approved, ts}>`）；**新建会话后再访问同一 host 会重新弹窗**（覆盖不跨会话、不持久化）。

#### E2E-NET-05 `unknown_domain: deny` → 直接拦不弹
- **前置**：画像 `unknown_domain: deny`，重启、建会话。
- **步骤**：访问不在白名单的域名。
- **预期**：**不弹窗**直接拦截（画像级禁问）；审计记 decision=deny。

#### E2E-NET-06 `approval_policy: never` 总闸 → 未知域名直接拒
- **前置**：`approval_policy: never` + 网络画像（白名单含 allow、其余未知），重启、建会话。
- **步骤**：访问白名单外域名。
- **预期**：**不弹窗直接拒**（`never` 是网络总闸，`unknown_domain` 不生效）；allow 白名单域名仍放行。

#### E2E-NET-07 `granular` 且 `network: false` → 未知域名直接拒
- **前置**：`approval_policy: {granular: {network: false}}` + 网络画像，重启、建会话。
- **步骤**：访问白名单外域名。
- **预期**：**不弹窗直接拒**（网络审批关闭）；allow 白名单仍放行。

#### E2E-NET-08 `network_rules` 精确规则优先于 domains
- **前置**：`dev` 画像 + 顶层 `network_rules`（如 `git.example.com: https → prompt`）；建会话。
- **步骤**：让 LLM 访问 `git.example.com`（命中 network_rules prompt，未在 domains 白名单）。
- **预期**：代理先比对精确 `network_rules`（forbidden > prompt > allow）→ 命中 prompt → 按总闸 + unknown_domain 弹窗确认；审计收到对应判定。

#### E2E-NET-09 审计闭环
- **前置**：上述任一网络用例后。
- **步骤**：查看服务端审计。
- **预期**：`tool.network_approval` 事件逐条落审计（`_map_resource` 记目标域名 host）；`logs/agent.log` 可见 host/decision/approved。

### 1.6 沙箱兜底 P3

> 客户端用 landstrip 建沙箱执行命令类工具（`landstrip run -p policy.json -- <cmd>`），policy.json 由策略包转换；Windows 为 AppContainer，**目录级粗粒度**兜底，文件级精细 deny 由服务端判定承担。`sandbox.required` 为真时命令类进沙箱；沙箱不可用（`doctor` 失败）→ **fail-closed**。
>
> **本机环境限制**：当前机器 landstrip.exe 从 G 盘被拒执行（EPERM）、AppContainer 建立失败（os error 5），属环境问题——`doctor` 失败走 fail-closed 是**预期行为**，见注意事项 4。以下用例中标「需可用沙箱环境」的需在有 landstrip 可用的机器验证。

#### E2E-SBX-01 `required && doctor ok` → 命令类进沙箱
- **前置**（需可用沙箱环境）：默认配置（`:workspace` 下发 `sandbox.required=true`），landstrip `doctor` 通过；建会话。
- **步骤**：让 LLM 执行一条命令类工具（`bash`）。
- **预期**：命令经 `landstrip run -p policy.json -- <cmd>` 执行，进程级目录兜底生效（如可尝试写受限目录）。

#### E2E-SBX-02 沙箱拦截 → trap 随结果回传
- **前置**（需可用沙箱环境）：同上。
- **步骤**：让 LLM 执行一条会触发沙箱拦截的命令（如写工作区外 / 系统目录）。
- **预期**：命令被拦，stderr 出现结构化 trap JSON（如 `{"Filesystem":["write","/xxx","seccomp"]}`）；客户端 `sandbox:take-traps` 取到并随 `/tool-result` 的 `sandbox_traps` 回传。

#### E2E-SBX-03 `required && doctor 失败` → fail-closed（命令不执行）
- **前置**：默认配置；本机环境（landstrip 不可用）即可；建会话。
- **步骤**：让 LLM 执行任意命令类工具（如 `bash` 跑 `echo hi`）。
- **预期**：命令**不执行**，客户端返回错误 `沙箱不可用：landstrip 未就绪`（exit_code=1）；若 `runSandboxed` 抛错则返回 `沙箱执行失败：...`。日志无 `tool.permission_denied`（这是客户端兜底，不是服务端拒绝）。

#### E2E-SBX-04 无沙箱时读工具仍正常
- **前置**：同上（本机沙箱不可用）。
- **步骤**：让 LLM 执行 `read_file` / `glob` / `grep`。
- **预期**：读工具**不接沙箱**，正常裸跑返回内容（沙箱只包命令类，fail-closed 只影响 bash/exec_command）。

#### E2E-SBX-05 `:full` 画像不建沙箱
- **前置**：`default_permissions: ":full"`，重启、建会话。
- **步骤**：让 LLM 执行命令类工具。
- **预期**：策略包 `sandbox.required=false`，命令**不进沙箱**直接执行。

#### E2E-SBX-06 文件级精细 deny 由服务端判定承担（不依赖沙箱）
- **前置**：默认配置（`:workspace` 的 `:deny_workspace`）；本机沙箱不可用亦可。
- **步骤**：让 LLM `write_file` / `read_file` 写读 `.env`、`.git/**`。
- **预期**：即使沙箱不可用，文件级 deny 也由服务端判定拦截（forbidden 注入错误，见 E2E-PERM-03/04），**不依赖** landstrip 的目录级兜底。

### 1.7 注意事项（测试人员）

1. **三态结果从三层观察**：`skip` → 客户端免确认直接执行；`needs_approval` → 客户端弹确认；`forbidden` → 服务端注入错误返回模型（**不弹窗**），看 `tool.permission_denied` 日志。别把「不弹窗」当成 bug——需判断是 skip 还是 forbidden。
2. **三态确认对 Build / Ask / Plan 一致**：客户端默认 Build 模式，服务端 Build 与普通分支均 `requires_approval=(permission == "needs_approval")`（`query_loop.py:1192/1209`）——**skip 免确认、needs_approval 弹确认、forbidden 拦截**（Build 仅多 `step`/`tool_call_id`）。测「免确认」用例在 Build 或 Ask 模式均可，无需切模式。
3. **权限只对工具调用生效**：纯聊天不触发任何权限逻辑，必须先引导 LLM 调工具。
4. **网络工具服务端不判域名**：`web_fetch` 等在网络画像下服务端恒 skip，域名拦截看客户端代理与 UI 弹窗，服务端只收审计。
5. **沙箱本机环境限制是预期**：`doctor` 失败时命令类按 fail-closed 拦截（E2E-SBX-03）属设计行为，不是回归。需测沙箱成功路径（E2E-SBX-01/02）时确保 `@deepseek-ai/dsh-sandbox-windows-acl` 可用、工作区为调用者所有。
6. **改 `permissions.yaml` 必须重启服务**，且**重建会话**（画像在会话创建时编译/解析符号路径）。
7. **建会话必须带 `workspace`**：不带则 `@WORKSPACE@` 解析为空，路径判定（根内/越界/deny）全部失真。
8. **`approval_policy: never` / `:full` 属危险配置**：测完务必改回 `on-request` / `:workspace`，否则后续会话权限全开。
9. **skip 反馈观察**：点「跳过」后服务端走 `append_skip_feedback`（`query_loop.py:1607`），上下文注入"用户跳过了"；若旧版客户端回传 `{status:'error'}` 无 `skipped:true`，该反馈不会触发（`skipped:true` 是 P1 修正点）。
10. **域名/确认弹窗超时**：网络确认 30s 超时默认拒（小于服务端 120s 的 `sync_waiter.wait`），挂太久不点等于拒绝。
11. **断线幂等**：auto-execute 按 `request_id` 幂等，重连重放 chunk 不会二次执行；不要因为重连后「又看到一次」误判为重复执行。
