## 1. 背景与问题

iWork 服务端运行在 Linux，客户端是 Electron（Windows / macOS / Linux）。**所有工具执行权均在客户端**——服务端把执行权经 `client.tool_request` 数据块**委派**给前端，前端必须响应，否则引擎卡在 WAITING_SYNC 直到超时。按来源分三类：

- **客户端工具（Client Tools）**：Electron 本地直接执行（`server/tools/dispatcher.py:15` `CLIENT_TOOLS` 含 `bash` / `read_file` / `write_file` / `edit_file` / `glob` / `grep` / `skill`）。其中 `skill` 的工具定义由服务端注入（`SKILL_TOOL_DEFINITION` 进 `server_tools`），但**执行仍在客户端**——读取本地 `SKILL.md` 返回内容。
- **客户端 MCP（Client MCP）**：Electron 转发到 MCP 子进程 / HTTP 连接执行。MCP 进程由客户端管理，服务端仅维护安装状态与工具清单（`dispatcher.py` 经 `set_client_mcp_tool_names()` 将客户端上报的 MCP 工具名归入 `ToolLocation.CLIENT`）。
- **服务端工具**：不涉及本地资源、直接读写服务端状态，由服务端执行：
  - **记忆工具**：`memory_search` / `recall` / `scene_read`（`dispatcher.py:10` `SERVER_BUILTIN_TOOLS`）→ `query_loop.py` `_execute_memory_search` / `_execute_recall_tool` / `_execute_scene_read` 直接读 DB。记忆的写入不由模型发起——L1 抽取、L2 场景整合都在后台由调度器自动完成（见《5-记忆模块》）。
    - `scene_read` 按场景名取全文，名字来自系统提示词末尾的 `<scene-navigation>` 块（只给名字 / 热度 / 摘要）；未命中回可用名字清单，每轮限次（默认 3）。三者都是只读，记 read-only 档，不落副作用账（`idempotency.py:14`）。
  - **task 工具**：团队 lead 把子任务派给子 agent（`query_loop.py:1454`）→ `_task_handler.execute()` 创建子会话执行。
  - **服务端 MCP 兜底**：未归入客户端的 MCP 工具经 `tool_dispatcher.dispatch` 路由到 `MCPToolRegistry`（`dispatcher.py:40`，按 `server_id.actual_tool` 解析）。
  - **plan_question（plan 模式）**：服务端拦截收集用户决策（`query_loop.py:1119`），非执行工具，仅 plan 模式流程用。

问题：**bash 在客户端本机执行，但 LLM 不知道客户端的 OS / shell。**

- LLM 拿到的 bash 工具描述是固定字符串 `"Execute a shell command in the workspace directory..."`，**不含 OS/shell**。
- 系统提示词（`server/engine/context.py` `ContextManager.build()`）无任何环境信息。
- 后果：LLM 默认生成 POSIX / Linux 命令，在 Windows 客户端上大量执行失败。

关联问题：权限引擎的路径判定也存在同类平台错位——服务端跑在 Linux 时，无法识别客户端传回的 Windows 盘符路径（`Path("G:\\论文2\\parse_baidu.ps1").is_relative_to("G:\\论文2")` 在 POSIX 上是 False，反斜杠被当作普通字符），已通过 `server/tools/permission.py` 的路径归一化修复（`_norm_slashes` / `_within` / `_relative_to`，见 §5 红线）。


## 3. Claude Code 的机制（调研实证）

### 3.1 执行侧：按 OS 选真实 shell

| 平台 | 选用的 shell | 说明 |
|---|---|---|
| **Windows** | Windows PowerShell 5.1 | 系统内置；`Get-ChildItem`/`Get-Content`/`Select-String` 等替代 Unix 工具；沙箱内外统一用 PowerShell，命令语法契约唯一 |
| **macOS** | 原生 `$SHELL`（默认 `/bin/zsh`） | 系统 bash 是老旧 3.2；BSD 工具与 GNU 有差异（sed/awk 参数、无 `grep -P`） |
| **Linux** | 原生 bash | 最干净 |

Windows 统一走 `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`（`-NoProfile -NonInteractive -ExecutionPolicy Bypass -Command`），不再依赖 Git Bash。

### 3.2 披露侧：固定工具描述 + 系统提示词注入（关键结论）

调研确认：Claude Code 的 Bash 工具 description 是**固定静态字符串**，**不含 OS**。它不动态改工具描述，而是运行时检测 OS / arch / shell / 项目根目录，**注入系统提示词**。Windows 上注入行为：

```
Shell: bash (use Unix shell syntax, not Windows — e.g., /dev/null not NUL, forward slashes in paths)
```

设计要点：**环境信息走系统提示词，工具描述保持稳定**。这样工具名与描述不随平台变化，LLM 的上下文稳定，而环境事实（OS / shell 语法差异）通过系统提示词持续可见。

### 3.3 shell snapshot 机制

- 启动后捕获一次 PATH，写入 `~/.claude/shell-snapshots/snapshot-<shell>-<id>.sh`。
- 每条命令以 `source snapshot 2>/dev/null || true && eval <cmd>` 形式执行，保证会话内 PATH 一致。
- **坑**：快照冻结了启动时刻的 PATH。GUI 启动时 PATH 极简，快照里没有 node/npm → 命令找不到。

## 4. 已知坑（对齐 Claude Code）

1. **Windows：PATH 不完整** → PowerShell 非登录不读 profile，app 继承的 PATH 可能没有 git/node → 客户端合并注册表持久 PATH（HKLM+HKCU）到命令 env。
2. **Windows：输出编码** → PowerShell 非交互输出走管道时为 OEM/GBK → 命令前置 `$OutputEncoding = [Console]::OutputEncoding = [System.Text.Encoding]::UTF8;`；客户端 `decodeBuffer` 做 UTF-8→GBK 回退兜底。
3. **Windows：原生命令退出码** → `git/node` 失败不会让 PS 进程非 0 退出 → 提示词强制命令结尾 `exit $LASTEXITCODE`。
4. **Windows：路径含空格括号** → 含空格/括号的路径在 PowerShell 里必须加引号包裹。
5. **macOS / Linux：快照冻结启动 PATH** → GUI 启动 PATH 极简时 node/npm 找不到（见 §3.3）。

## 5. iWork 落地设计（复刻 Claude Code）

### 5.1 客户端 `G:\AI-coding\agent-client`

1. **bash 执行按 `os.platform()` 选 shell**：`win32 → Windows PowerShell`（沙箱内外统一，语法契约唯一）/ `darwin → $SHELL` / `linux → bash`；cwd 用绝对路径，会话内 `cd`/`Set-Location` 持久。
2. **建会话上报 `shell_env`**：取值 `"powershell" | "zsh" | "bash"`。
3. **工具描述保持固定**（对齐 Claude Code 的披露侧设计），不随平台变化。

### 5.2 服务端 `G:\AI-coding\i-work`

**流程：**

1. **接收并存储**：客户端建会话时上报 `shell_env`，服务端在会话上接收并持久化该字段（默认空串）。
2. **上下文注入**：每次构建 LLM 上下文时，按会话的 `shell_env` 从内置映射表查取对应提示词块；命中即追加到系统提示词，空串 / 未识别则不注入。
3. **子会话继承**：多 agent 协作产生的子会话继承父会话的 `shell_env`。

服务端内置一张 `shell_env → 提示词块` 映射表。**三档完整提示词文案：**

`powershell`（Windows，客户端 Windows PowerShell 执行，沙箱内外统一）：
```text
Shell: Windows PowerShell 5.1
- 用 PowerShell 语法写命令，不要用 bash/Unix 语法
- 常用替代：Get-ChildItem（ls/dir）/ Get-Content（cat）/ Set-Content / Add-Content（>>）/ Select-String（grep）/ Copy-Item（cp）/ Move-Item（mv）
- 变量用 $var、环境变量用 $env:VAR；多条命令用 ; 分隔；换行续行用反引号 `
- 路径用 Windows 风格（G:\foo 或 G:/foo），含空格/括号时加引号
- 删除类命令（rm / del / Remove-Item）禁止使用
- 原生命令（git/node 等）失败不会自动退出：命令结尾追加 exit $LASTEXITCODE 保证退出码正确
- 沙箱启用时写入仅限工作区内，工作区外写入会被拒绝
```

`zsh`（macOS，客户端原生 `$SHELL`）：
```text
Shell: zsh (macOS 原生 shell)
- 使用 POSIX/Unix 语法写命令
- 注意 BSD 工具集与 GNU 的差异：sed/awk 参数不同；没有 grep -P，请用 grep -E 或 -e
- 系统 bash 是老旧 3.2，不要使用 bash 4+ 特性（关联数组、${var,,} 大小写转换等）
```

`bash`（Linux，客户端原生 bash）：
```text
Shell: bash (Linux)
- 标准 POSIX/GNU 环境，使用常规 POSIX 语法写命令即可
```

### 5.3 红线：工具名恒为 `bash`

工具名是权限体系的键，跨平台必须一致，改名会破坏：

- `server/tools/permission.py:39` `COMMAND_TOOLS = {"bash", "exec_command"}` —— 命令类工具归类
- `server/permissions.yaml` `tool_rules` —— `"tool:bash"` 前缀规则
- `server/tools/dispatcher.py` —— `CLIENT_TOOLS` 精确匹配
