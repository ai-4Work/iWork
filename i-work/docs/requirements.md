# iWork 需求文档

> 基于原型 mockup/index.html，版本 v0.1

---

## 1. 产品概述

### 1.1 产品定位

iWork 是一个**自主 AI 工作助手**，面向日常办公与代码开发场景。用户通过自然语言描述任务，AI 自动执行思考、规划、工具调用等步骤，最终交付结果。

### 1.2 目标用户

- 需要处理文档、报表、邮件的办公人员
- 需要代码分析、调试、重构的开发人员
- 需要跨工作空间管理多项目的技术管理者

### 1.3 核心价值

- **自主执行**：AI 自主拆解任务并调用工具，用户无需逐步指导
- **过程透明**：思考链与工具调用过程可折叠查看，增强可信度
- **多工作空间**：支持在不同项目目录间切换
- **可扩展性**：通过 Skills / MCP 插件机制扩展能力

## 2. 功能需求

### 2.1 侧边栏

#### 2.1.1 品牌标识
- 显示产品 Logo 及名称 "iWork"
- 不可折叠，始终可见

#### 2.1.2 新建任务
- 侧边栏置顶的醒目按钮，点击后创建空白新任务并自动切换到新任务视图
- 新任务默认标题为"新建任务"

#### 2.1.3 配置入口
以导航列表形式提供以下入口，位于"配置"分组标题下方：

| 入口 | 说明 |
|------|------|
| Skills 配置 | 管理内置/Hub/自定义 Skills 的安装与启停 |
| MCP 配置 | 管理 MCP 服务的连接与配置 |
| 记忆配置 | 管理聊天记忆与 Rules |
| 专家和专家团 | 管理专家角色与团队协作配置 |
| 自动化 | 配置自动化任务与工作流 |

- 选中项高亮

#### 2.1.4 任务列表
- 位于"工作任务"分组标题下方
- 每条任务显示：标题（单行省略）、时间戳
- 当前选中任务高亮
- 列表可滚动
- 任务项支持右键菜单：重命名、复制、删除
- 新消息发送后，任务标题自动截取消息前 20 字符

#### 2.1.5 用户信息
- 底部固定显示用户头像（首字母）和用户名
- 上方有分割线与任务配置区隔开

### 2.2 首页右栏

首页右栏是位于主聊天区域右侧的固定配置面板，用于集中管理当前任务的工作场景、工作空间、模型和使用模式。该面板在所有任务状态下持续可见。

#### 2.2.1 工作场景模式

两种预设工作场景，通过切换按钮选择。不同场景使用不同的系统提示词（System Prompt），影响 AI 的行为偏好和回答风格。

| 场景 | 说明 | 系统提示词侧重 |
|------|------|----------------|
| 日常办公 | 面向文档处理、邮件起草、报表生成、信息整理等办公任务 | 简洁清晰、结构化输出、注重效率 |
| 代码开发 | 面向代码分析、调试、重构、脚本编写等开发任务 | 技术深度、代码优先、关注最佳实践 |

- 默认选中"日常办公"
- 切换场景不影响当前对话历史，仅影响后续 AI 回复的行为偏好
- 每个任务独立维护当前场景模式
- 场景模式与欢迎页的快捷入口按钮状态双向同步（参见 2.3.1）

#### 2.2.2 输入增强

输入增强是指在消息输入框中通过特殊前缀符号触发的高级交互能力。

**@ 文件引用**：
- 在输入框中键入 `@` 符号，触发文件搜索面板
- 搜索范围为当前选中的工作空间目录
- 支持文件名模糊匹配，实时显示匹配结果
- 选中文件后，文件名以内联标签形式嵌入输入框
- AI 处理消息时，被引用文件的内容自动注入上下文
- 单条消息可引用多个文件

**/ 技能与指令调用**：
- 在输入框中键入 `/` 符号，触发技能/指令列表面板
- 面板列出：已安装的 Skills 和内置指令
- 选中后以标签形式嵌入输入框
- 支持组合使用：同一消息中可同时包含 @ 引用和 / 调用

**交互约束**：
- @ 和 / 仅在工作空间已选定或自动创建后可用
- 文件引用数量上限由工作空间上下文窗口大小决定

#### 2.2.3 工作空间

工作空间是 AI 操作的**根目录**，AI 的读写操作被严格限制在该目录范围内。

**选择方式**：
- 下拉选择器显示当前工作空间路径
- 下拉列表包含：
  - 最近使用的工作空间（最多保留 5 个）
  - "浏览选择目录..."选项（触发系统原生目录选择器）
- 选中后路径立即生效，应用于当前任务的所有后续对话

**沙箱约束**：
- AI 的文件读写、Shell 执行等操作**仅限工作空间目录内**
- 任何尝试访问工作空间外的操作将被拦截并提示用户

**默认行为**：
- 若用户未主动选择工作空间，系统自动在用户主目录下创建 `.iwork/<任务ID>/` 作为默认工作空间
- 默认工作空间包含以下预建子目录：
  - `workspace/` — AI 工作文件输出目录
  - `logs/` — AI 执行日志
- 用户可随时将默认工作空间更换为真实项目目录

**持久化**：
- 工作空间选择按任务独立存储
- 切换任务时自动恢复该任务绑定的工作空间路径

#### 2.2.4 模型选择

用户可选择不同的 AI 模型来执行当前任务，支持从预设列表中选择或输入自定义模型。

**预设模型列表**：

| 模型 | 场景建议 |
|------|----------|
| Claude Opus 4.7 | 复杂推理、长文本处理（默认） |
| Claude Sonnet 4.6 | 日常任务、快速响应 |
| GPT-4o | 通用对话、多模态任务 |
| DeepSeek V3 | 代码生成、中文优化 |

**自定义模型**：
- 下拉列表底部提供"自定义模型..."选项
- 点击后出现文本输入框，用户可直接输入任意模型名称或标识符
- 自定义输入的模型仅对当前任务生效，不加入预设列表

**切换行为**：
- 切换模型后，后续消息均使用新模型
- 已生成的历史消息不受影响
- 模型选择按任务独立存储

#### 2.2.5 使用模式

三种使用模式决定了 AI 在执行任务时的行为策略和自主程度。

| 模式 | 名称 | 行为 | 工具调用 | 文件访问 |
|------|------|------|----------|----------|
| Ask | 问答模式 | 纯对话问答，AI 仅生成文本回复 | 不调用 | 不访问 |
| Plan | 规划模式 | AI 先生成执行计划，等待用户确认后再自动执行 | 确认后调用 | 确认后访问 |
| Build | 构建模式 | AI 立即行动，但每个主要步骤暂停等待用户确认 | 调用，每步确认 | 访问，每步确认 |

- 默认选中"Build（构建模式）"
- 三种模式以分段按钮组展示，当前选中项高亮
- 模式选择按任务独立存储

**模式详细说明**：

**Ask（问答模式）**：
- AI 不调用任何工具，不访问文件系统
- 仅基于对话上下文和内置知识生成回复
- 适用于：信息咨询、概念解释、方案讨论等无需操作的场景

**Plan（规划模式）**：
- AI 收到任务后，先输出结构化的执行计划（步骤列表、预期产出）
- 用户可对计划进行审核、修改或确认
- 用户确认后，AI 按计划自动执行，过程中不再逐步询问
- 适用于：复杂多步骤任务、需要前置审核的场景

**Build（构建模式）**：
- AI 收到任务后立即开始执行
- 在每一步操作（文件写入、Shell 执行、API 调用等）前暂停等待用户确认
- 用户可选择：确认执行、跳过此步、终止任务
- 适用于：需要精细控制每一步操作的场景

### 2.3 聊天主界面

#### 2.3.1 欢迎状态

当任务无消息时显示：
- 居中 Logo + 标题："iWork，您的AI工作助手"
- 快捷入口按钮：**日常办公**、**代码开发**（按钮组，可切换选中）
  - 该快捷入口与首页右栏的"工作场景模式"（2.2.1）状态双向同步，点击快捷按钮等同于在右栏中切换场景模式

#### 2.3.2 对话状态

任务有消息后切换为对话布局：
- 消息区域占满剩余空间，可滚动
- 输入区域固定在底部

#### 2.3.3 消息渲染

**用户消息**：
- 右对齐，气泡样式与 AI 消息区分
- 显示用户头像

**AI 消息**：
- 左对齐，气泡样式与用户消息区分
- 显示 AI 头像
- 内联代码使用等宽字体区分
- 支持换行

**思考与工具调用区域**（可折叠）：
- 位于 AI 气泡内，最终回复文字上方
- 折叠头显示"思考与工具调用"及工具数量，执行中时追加"执行中..."标签
- 折叠体包含：
  - 思考文本：展示 AI 分析推理过程
  - 工具调用列表，每项展示：工具名称、执行的命令、详情（如文件名、行数）、执行结果、状态标签（执行中 / 完成）
- 工具执行完成后自动折叠该区域

#### 2.3.4 输入区域

**欢迎状态**：输入框在欢迎页下方居中显示。

**对话状态**：输入框固定在底部。

**输入框**：
- 多行文本输入，自动扩展高度
- placeholder：`输入任务，@引用文件， /调用技能与指令`
- 聚焦时有视觉反馈
- 右下角发送按钮，输入框有内容时即可点击发送，不受 AI 处理状态限制
- Enter 发送，Shift+Enter 换行

**消息队列（处理中连续输入）**：
- AI 回复进行中时，用户可在输入框继续键入并发送新消息，新消息进入等待队列
- 队列以列表形式展示在输入框上方，每条显示：序号徽章、消息文字预览（超长截断）、移除按钮
- 当前 AI 回复完成后，自动取出队首消息作为下一条输入发送，继续处理
- 队列为空时列表自动隐藏
- 支持手动移除队列中的任意消息

> 工作空间、模型、使用模式的选择器已整合至首页右栏（参见 2.2.3、2.2.4、2.2.5），不再作为输入区域的工具栏控件展示。

#### 2.3.5 状态栏

- 位于主界面顶部，以只读形式展示当前任务的配置摘要
- 显示内容（紧凑排列）：
  - 当前使用模式标签（Ask / Plan / Build）
  - 当前模型名称
  - 当前工作空间路径（超长时省略号截断）
- 所有配置修改通过首页右栏完成，状态栏仅做只读展示

### 2.4 Skills 配置面板

> **用户绑定**：Skills 配置按用户账号隔离存储。每位用户独立管理已安装 Skills 和自定义 Skills。Hub 中的 Skill 由后台管理平台统一配置和发布，用户侧仅可浏览和安装，不可修改 Hub 内容。安装状态按用户记录，切换用户后 Skills 配置切换为对应用户的数据。

#### 2.4.1 页面结构
- 从侧边栏点击进入后，主界面被替换为全宽配置面板
- 顶部：返回按钮 + 标题"Skills 配置"
- 内容区：Tab 切换 + 搜索 + 卡片网格

#### 2.4.2 Tab 页

**Hub 页**：
- Hub 中的 Skill 来源于**后台管理平台**，由管理员统一配置、审核和发布
- 发布后，所有用户可在 Hub 中浏览和搜索
- 展示可安装的 Skill 卡片列表（含搜索框）
- 每张卡片：图标 + 名称 + 描述 + 分类标签 + 安装/已安装按钮
- 安装状态切换：安装 ↔ 已安装
- 用户仅可安装/卸载，不可修改 Hub 中 Skill 的定义和内容

**已安装页**：
- Hub 已安装 + 内置 Skills 两部分
- 内置 Skills 不可卸载，无操作按钮

**自己添加页**：
- 上传 Skill 按钮
- 自己创建按钮（弹出 Modal 输入名称）
- 已添加的自定义 Skill 列表（可删除）

#### 2.4.3 卡片交互
- 卡片 hover 时有视觉反馈
- 已安装的卡片有左侧边框指示

### 2.5 MCP 配置面板

> **用户绑定**：MCP 配置按用户账号隔离存储。每位用户独立管理 MCP 服务连接（endpoint、认证凭据等）。Hub 中的 MCP 服务由后台管理平台统一配置和发布，用户侧仅可浏览和安装。连接配置按用户记录，切换用户后 MCP 配置切换为对应用户的数据。

结构同 Skills 配置面板，区别：
- Hub 数据为 MCP 服务（GitHub MCP、Slack MCP 等）
- 分类标签区分于 Skills
- 安装/卸载逻辑独立

### 2.6 记忆配置面板

> **用户绑定**：记忆（聊天记忆 + Rules）按用户账号隔离存储，每位用户拥有独立的记忆条目和 Rules 集合，用户之间互不可见。切换用户后，记忆数据切换为对应用户的数据。

#### 2.6.1 聊天记忆
- 列表展示记忆条目：内容 + 时间 + 编辑按钮 + 删除按钮
- 点击编辑弹出 Modal，可修改记忆文本
- 点击删除移除条目，Toast 确认

#### 2.6.2 Rules
- 同聊天记忆结构
- 功能一致（编辑、删除）

### 2.8 用户认证与登录

#### 2.8.1 概述

iWork 支持多用户体系，每位用户拥有独立的账号和数据空间。Skills 配置、MCP 服务配置、记忆（聊天记忆与 Rules）均与用户账号绑定，确保数据隔离。

#### 2.8.2 登录与注册

**注册**：
- 支持邮箱 + 密码注册
- 注册成功后自动登录并跳转至主界面

**登录**：
- 支持邮箱 + 密码登录
- 支持第三方 OAuth 登录（GitHub、Google）
- 登录成功后服务端签发 JWT Token，后续所有 API 请求携带 Token 鉴权
- 支持"记住我"选项——勾选后 Token 持久化存储；未勾选则关闭浏览器后 Token 失效

**登录页面**：
- 未登录用户访问应用任意路径时，重定向至登录页面
- 登录页面展示产品 Logo + 名称，居中展示登录/注册表单
- 登录成功后跳转至用户上一次活跃的任务，若无历史任务则进入欢迎状态

**Token 管理**：
- Token 过期后 API 请求返回 401，前端自动跳转登录页
- 支持 Token 刷新机制（Refresh Token），避免频繁重新登录

#### 2.8.3 用户数据绑定与隔离

以下配置和资源按用户账号强绑定，用户之间数据完全隔离：

| 资源 | 绑定方式 | 说明 |
|------|----------|------|
| **Skills 配置** | 用户级 | 每位用户独立管理已安装 Skills、自定义 Skills；Hub 列表为全局共享，但安装状态按用户存储 |
| **MCP 配置** | 用户级 | 每位用户独立管理 MCP 服务连接（endpoint、认证凭据等）；服务列表为全局共享，但连接配置按用户存储 |
| **记忆（聊天记忆 + Rules）** | 用户级 | 每位用户拥有独立的记忆条目和 Rules 集合，互不可见 |
| **任务列表** | 用户级 | 每位用户仅可见自己创建的任务 |
| **工作空间路径** | 用户级 | 每位用户独立维护最近使用的工作空间列表（上限 5 个） |
| **模型偏好** | 任务级 | 模型选择按任务独立存储，任务归属于用户，间接实现用户隔离 |

**设计原则**：
- 用户 A 登录后，仅加载用户 A 的 Skills 安装列表、MCP 连接配置、记忆和任务
- 切换用户登录后，上述数据全部切换为新用户的数据
- 用户之间不可互相访问对方的配置和数据

#### 2.8.4 用户信息与退出

- 侧边栏底部显示当前登录用户头像（首字母）和用户名（参见 2.1.5 节）
- 点击用户信息区域弹出菜单：
  - **个人信息**：查看/修改用户名、邮箱
  - **退出登录**：清除本地 Token 及缓存数据，跳转至登录页

## 3. 技术栈建议

| 层级 | 建议方案 |
|------|----------|
| 前端框架 | React / Vue 3 |
| UI 组件库 | Tailwind CSS + shadcn/ui（或自建） |
| 状态管理 | Zustand / Pinia |
| 后端 API | Node.js + Express / Python FastAPI |
